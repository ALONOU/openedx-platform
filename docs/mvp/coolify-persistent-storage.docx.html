Persistance des données sur Coolify (serveur alonu)

Objectif : ne perdre aucune donnée entre deux déploiements.

Comment ajouter un Storage : Ouvre l’app dans Coolify → onglet Storages → Add → renseigne Name et Destination Path (type Volume).

1. Deux cas selon le type d’application

TypeOù configurerSection Storages Coolify
Docker ComposeDans le docker-compose.yaml (volumes: ./data/...)Rien à ajouter
Dockerfile / Image / NixpacksInterface Coolify : Storages → AddC’est ici que tu ajoutes les chemins

storage → /app/storage ; bootstrap-cache → /app/bootstrap/cache.

6. togo-fedsport-network

storage → /app/storage ; bootstrap-cache → /app/bootstrap/cache.

8. administration-territoriale

storage → /app/storage ; bootstrap-cache → /app/bootstrap/cache.

14. openedx-platform-mvp

Si Docker Compose (lms, cms, mysql…) : rien. Si une seule image : data → /app/data, media → /app/media.

15. archivage

storage → /app/storage ; data → /app/data ; bootstrap-cache → /app/bootstrap/cache.

4. Résumé

  • Storages = persistance pour les apps Dockerfile / Image / Nixpacks. Création dans Coolify : Storages → Add.
  • Docker Compose = persistance déjà dans le compose (volumes: ./data/...).
  • Une fois chaque Storage ajouté, les redéploiements ne feront plus perdre les données.
